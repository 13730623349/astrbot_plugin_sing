# 唱歌翻唱 · astrbot_plugin_sing

给她一个歌名，她用**你自己的 RVC 音色**唱整首歌，唱完把语音发到聊天里。

不是「读歌词」，是真的换声——把原唱的人声分离出来，换成你训练的音色，再和伴奏混回去。

---

## 链路

```
/唱歌 心湖
   ↓
搜歌（歌曲海 / 网易云兜底）
   ↓
下载原曲  →  downloads/
   ↓
rvc-next 分离人声（karaoke 预设）
   ↓
换成你的音色（xilian）
   ↓
和伴奏混回
   ↓
成品存一份 → output_sing/
   ↓
压成 QQ 能收的形式 → 发语音
```

一首 4 分钟的歌，全流程约 **60~120 秒**。

---

## 前置条件

需要本机跑着 **rvc-next**（默认 `127.0.0.1:7868`）。

```bash
# 起服务
schtasks /run /tn "TTS-RVC-Service"
```

查服务状态：

```bash
curl -s http://127.0.0.1:7868/api/v1/app/health
# {"status":"ok"}
```

显存 8GB 以下建议保持 `preset: karaoke`。爆显存会自动降级重试（`karaoke → vocals-aggressive → dereverb`）。

## 指令

### `/唱歌 <歌名>`

搜歌。找到多个版本会列出来让你挑：

```
《心湖》找到 7 个版本，要唱哪个？
1. 心湖雨又风 — 高胜美
2. 心湖里起涟漪 — 邓丽君
3. 心湖雨又风 — 高胜美
4. 心湖 — 王森地
5. 心湖 — 张靓颖
6. 心湖 — 甄妮
7. 心湖 Lotus of Heart — 莹我从
回一个数字，或者回「取消」。
```

**回数字**挑版本，**回「取消」**放弃，90 秒不回自动作废。

### `/唱歌 <歌名> <歌手>`

跳过选择，直接指定版本：

```
/唱歌 心湖 张靓颖
```

### `/唱歌 <歌名> --重唱`

**强制重新转换**，不用已有成品。别名 `-f`。

成品目录里已经有这首歌时，插件默认直接发旧的、跳过下载和转换。加这个参数就重新走全流程。

### `/点歌 <歌名>`

和 `/唱歌` 完全一样，别名。

### `/唱歌列表 <歌名>`

只搜不唱，看看有哪些版本可选。

### `/唱歌状态`

检查服务是否就绪：

```
rvc-next：正常
可用音色：xilian, xuexi
唱歌用：xilian
分离预设：karaoke
变调：+0 半音
```

如果显示「← 模型库里没有这个！」，说明配置里的 `voice_id` 写错了。

### `/唱歌帮助`

指令速查。

### `/发歌`

把 `output_sing` 里**最新的一首**重发一遍。不重新转换，纯测发送用。

### 聊天里直接点歌（推荐）

**不用打指令**，像平时说话一样就行：

```
妈咪，我想听你唱心湖
唱首虫儿飞给我听
给我唱一首《起风了》吧
来一首周杰伦的晴天
你会唱虫儿飞吗
给我唱个温柔版虫儿飞
我想听《虫儿飞》
```

两条路都会接住：

| 路径 | 说明 |
|---|---|
| **模型主动调工具** | `sing_song` 工具，最自然，能理解各种说法 |
| **关键词兜底** | 模型没动静时，插件自己从句子里抠歌名 |

关掉兜底：配置里 `chat_trigger: false`。

**不会误触发的例子**（都验证过）：

```
我想听你唱歌        ← 没指定歌名
唱个歌呗            ← 没指定歌名
我想听你说说话      ← 不是歌名
今天好累啊          ← 无关
你会不会累          ← 无关
```

宁可漏掉，也不误判——误判会打断正常聊天。

### LLM 工具 `sing_song`

给模型的工具定义，参数两个：

| 参数 | 说明 |
|---|---|
| `song` | 歌名，只填歌名本身，不带「我想听」这类话 |
| `artist` | 可选歌手名，对方明确提了才填 |

返回给模型的话里会提示它「只说一句自然的话，不要播报歌名、不要重复点歌」。

需要 `llm_tool_enabled: true`。

## 配置

在 WebUI 的「唱歌翻唱」插件配置页改。

| 项 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `rvc_url` | `http://127.0.0.1:7868` | rvc-next 地址，**不要带 `/api`** |
| `voice_id` | `xilian` | 唱歌用的音色 id |
| `preset` | `karaoke` | 人声分离预设 |
| `pitch` | `0.0` | 变调半音数 |
| `max_seconds` | `300` | 最长处理时长，超过拒绝（`0` 不限制） |
| `timeout` | `900` | 等转换的上限秒数 |
| `send_text` | `true` | 发语音前先说一句歌名 |
| `group_on` | `false` | 群聊也能点歌 |
| `llm_tool_enabled` | `true` | 允许模型自己点歌 |
| `list_count` | `8` | 候选列表条数 |
| `download_dir` | `D:\...\RVC\sing\downloads` | 原音频存放 |
| `output_dir` | `D:\...\RVC\sing\output_sing` | 成品存放 |
| `reuse_cache` | `true` | 唱过的歌直接复用成品 |
| `chat_trigger` | `true` | 聊天里直接点歌（关键词兜底） |
| `remember_singing` | `true` | 唱完记进她的会话 |

### 分离预设怎么选

| 预设 | 显存 | 说明 |
|---|---|---|
| `karaoke` | 低 | 默认，稳定，4 分钟歌稳跑 |
| `vocals` | **高** | BS-RoFormer，音质最好，8GB 显存容易 OOM |
| `vocals-aggressive` | 低 | 分离更狠，可能吃掉和声 |
| `dereverb` | 低 | 去混响 |

### 时长上限

`max_seconds` 在**下载完成后、转换开始前**检查真实时长：

```
下载完成 4.26 MB
《心湖》279 秒 ≤ 300 秒 → 继续转换
```

超限时不会白白占用显存，直接拒绝并告诉你实际时长：

```
《某某歌 — 某某》有 512 秒，超过了 300 秒上限。
要么换个短一点的版本，要么改高上限。
```

设 `0` 表示不限制。搜索结果的元数据里没有时长信息，所以必须下载完才能判断。

### 变调

| 场景 | 建议 |
|---|---|
| 同性别源 | `0` |
| 男声源 → 女声模型 | `+12` |
| 女声源 → 男声模型 | `-12` |

```
D:\GAME\Codex++Ollama\RVC\sing\
├── downloads\       原音频（下载的歌曲）
│   └── 心湖-张靓颖.mp3
└── output_sing\     成品（换声后的歌）
    └── 心湖-张靓颖_1122-0227.mp3
```

成品命名：`歌名-歌手_月日-时分.mp3`，重名自动加 `_1`、`_2`。

两个目录都在配置里能改，默认放 D 盘不占 C 盘。

## 她知道自己唱了

唱完不是冷冰冰地甩一个文件过来。发送前会**用她自己的口吻生成一句话**：

```
模型生成（不是固定文案）：
"呼……唱完了，有点喘。你听听看嘛"
```

这句话有三个作用：

1. **附在语音前面发给你**，不像机器播报
2. 让她在生成的那一刻「经历」了唱歌这件事
3. 记进她的会话：`[歌] 我刚唱完《心湖》（张靓颖），已经用语音发过去了…我当时说的是：「…」`

所以下一轮你问「你刚才唱的什么」，她记得。

### 生成失败怎么办

拿不到 provider 或生成出错时，退回空文案，语音照发，不影响主流程。

### 关掉

配置 `send_text: false` 关闭这句话；`remember_singing: false` 只关记忆、保留说话。

## 成品缓存

成品目录里已经有这首歌（**歌名 + 歌手相同**）时，插件直接发旧的，**跳过下载和转换**：

```
[sing] 命中缓存 心湖-张靓颖_1122-0227.mp3，跳过转换
```

匹配方式是按 `歌名-歌手_` 前缀找，取最新一版。

一首 4 分钟的歌省下 60~120 秒和一次显存占用。

### 什么时候会用旧版本

- 同一首歌、同一歌手，之前唱过 → 直接发旧的
- 想重新唱（换音色、改了 pitch、觉得之前唱得不好）→ 加 `--重唱`
- 歌手名对不上（比如之前存的标签是「华语群星」，这次选「张靓颖」）→ 不会命中，会正常重转

关掉这个功能：配置里 `reuse_cache: false`。

## 音质说明（重要）

**QQ 语音气泡最高只有 24kHz 单声道。**

这是 QQ 的 SILK 编码协议限制，第三方无法突破。NapCat 在发送前会强制：

```python
# AstrBot 的 tencent_record_helper.py
if channels == 2:
    pcm_data = audioop.tomono(pcm_data, sampwidth, 0.5, 0.5)  # 强制单声道
if rate not in _PYSILK_SUPPORTED_RATES:
    pcm_data = audioop.ratecv(..., rate, 24000, None)          # 降到 24kHz
```

所以无论源文件是 48kHz 立体声还是别的，**发到 QQ 都会变成 24kHz 单声道**。听起来会比本地原文件闷、高频少，这是平台上限，不是插件的问题。

想听原音质，去 `output_sing` 目录直接播文件，或者用文件形式发（`4.26 MB` 的 mp3 完全无损）。

### 发送方式

插件里的 `_send_audio()` 做了 MP3 直传优化：

```
MediaResolver(preserve_mp3=True) → mp3 原始字节 → base64 (5.68 MB)
```

而不是用 `Record`（它会强制转 48kHz 立体声 WAV，base64 后 **68 MB**，QQ 根本发不出去）。

失败时会自动回退到 `Record` 普通链路。

## 音源

| 来源 | 用途 |
|---|---|
| **歌曲海**（`gequhai.com`） | 主搜索源，走酷我曲库 |
| **网易云**（`gdstudio.xyz`） | 兜底，歌曲海取不到流时切 |

## 显存不够的自动降级

```
karaoke → vocals-aggressive → dereverb
```

每次失败会先调 `/api/v1/compute/release` 释放显存，等 5 秒再试下一个预设。

三个都失败才报错。

## 开发踩坑记录

### ① 选歌别用 SessionWaiter

`SessionWaiter.register_wait()` **不会**把 filter 登记进全局 `FILTERS`（那是 `@session_waiter` 装饰器干的事）。没登记 → 用户回的数字不会被拦 → 漏给大模型 → 它会自己乱调 `sing_song`。

而且插件一重载，全局 `FILTERS` 就失效。

**现在的方案：** 插件自己维护 `_pending` 表 + `@filter.regex(r"^\s*(?:\d+|取消|算了|不唱了|q)\s*$")`，只在整条消息是数字或取消词时激活。

### ② `Record.convert_to_base64()` 会重编码

它写死 `target_format="wav"`，把 mp3 变成 48kHz 立体声。4 分半的歌 base64 后 68MB。

**解法：** 别用 `Record`，走 `_send_audio()` 用 `MediaResolver(preserve_mp3=True)` 直接拿原始字节。

### ③ 歌曲海 ID3 标签不可信

见上文「音源」一节。别拿去校验。

---

## 已知限制

- **热重载不生效**：AstrBot 的 `reload()` 单插件分支漏了清理 `sys.modules`，`__import__` 命中缓存拿到旧代码。**必须重启整个 AstrBot**。
- **QQ 语音 24kHz 上限**：见上文音质说明，平台硬限制。
- **等待选歌只在内存里**：插件重启会丢失待选列表，此时回数字会被当普通聊天。
